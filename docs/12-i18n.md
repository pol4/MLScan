# 12. Локализация интерфейса и сообщений (RU/EN)

Документ описывает подсистему i18n: переключатель языка в UI, глобальную настройку языка всей
системы и перевод сообщений сервисов, находок и отчётов. Реализация — [`deploy/i18n/i18n.py`](../deploy/i18n/i18n.py).

## 1. Что локализуется

| Слой | Что переводится |
|------|-----------------|
| UI аналитики | все подписи: вход, дашборд, карточка артефакта, отчёты, страница настроек |
| Сообщения сервисов | ошибки и уведомления testing / integrations / ops / ingest (в т.ч. алерты) |
| Причины вердикта | `service_reason` («Максимальная серьёзность …», «Опасные конструкции уровня …») |
| Находки | заголовки и доказательства (`A-01`, `EXEC-02`, `FMT-01`, `BD-01`, …), включая исторические записи |
| Отчёты | Markdown, JSON и SARIF — на языке запроса |

Не переводятся **канонические идентификаторы**: значения `verdict` (`Malicious`, `Dangerous`,
`Needs review`, `Safe`, `Inconclusive`), `severity` (`critical/high/medium/low/info`),
`policy.action` (`block/quarantine/allow`) и `check_id`. По ним фильтруют UI и API, строятся
CSS-классы и принимаются решения — это машинные значения.

## 2. Уровни выбора языка

Приоритет (старший перекрывает младший):

1. **Явный запрос** — `?lang=ru|en` в URL или заголовок `X-MLScan-Lang` (API/CI).
2. **Пользовательская настройка** — cookie `mlscan_lang` (ставится переключателем в шапке UI).
3. **`Accept-Language`** клиента.
4. **Глобальная настройка системы** — таблица `settings` в PostgreSQL (ключ `language`).
5. **Значение при запуске** — переменная окружения `MLSCAN_LANG` (ConfigMap/Deployment, по умолчанию `ru`).

Пункты 4–5 обеспечивают требование «глобально для всей системы»: все сервисы возвращают
сообщения на выбранном языке, а администратор может сменить его на лету (кэш — 30 с).

## 3. Переключатель языка в UI

В шапке каждой страницы — `Язык: RU | EN`. Ссылка ведёт на `/lang?set=<код>&next=<путь>`:
сервис ставит cookie `mlscan_lang` (на год, `Domain=.mlscan.local`) и возвращает пользователя
на ту же страницу. Дополнительно язык можно задать параметром `?lang=en` без изменения cookie.

## 4. Глобальная настройка (администратор)

* **UI** — страница `/settings` (ссылка в шапке видна роли `admin`): выбор языка системы и
  сохранение (`POST /settings/language`).
* **API (ops)** — `GET /settings` (текущий глобальный язык, язык запуска, поддерживаемые) и
  `POST /settings/language?lang=en` (только роль `admin`).
* Значение хранится в таблице `settings` (`key='language'`), создаётся автоматически; при
  отсутствии БД используется язык запуска. Изменение пишется в `audit_log`.

Проверка:

```bash
curl -H "Authorization: Bearer $ADMIN_KEY" http://<ops>/settings
curl -X POST -H "Authorization: Bearer $ADMIN_KEY" "http://<ops>/settings/language?lang=en"
```

## 5. Как устроен перевод

Две независимые части модуля:

1. **Каталог `CATALOG`** — ключи вида `ui.overview`, `dash.upload`, `msg.scan_timeout` со
   значениями `ru`/`en`. Сервисы используют `t(key, lang, **fmt)`.
2. **Правила `_RULES`** — перевод «свободных» строк, которые сервисы уже отдали как данные:
   заголовки находок, причины вердиктов, ошибки загрузки. Функция `tr(text, lang)` применяет
   правила, `tr_list`/`tr_phrase` умеют переводить составные значения (списки через `, ` и `; `,
   конструкции «подпись: число»).

Такой подход позволяет показывать на английском **исторические** записи, сохранённые в БД и
evidence до внедрения i18n, без миграции данных: перевод выполняется при отображении.

## 6. Развёртывание

Модуль раскладывается ConfigMap `mlscan-i18n` во все namespace `mlscan-*` и монтируется в
`/opt/i18n` (аналогично `mlscan-authz` → `/opt/auth`); сервисы получают `MLSCAN_LANG` из
переменных окружения. Скрипты `deploy/stage{2,3,4,5}/apply.sh` и `deploy/v2/ingest/apply.sh`
создают ConfigMap автоматически.

```bash
kubectl -n mlscan-analytics create configmap mlscan-i18n \
  --from-file=i18n.py=deploy/i18n/i18n.py --dry-run=client -o yaml | kubectl apply -f -
kubectl -n mlscan-analytics rollout restart deploy/mlscan-analytics
```

## 7. Проверка

```bash
# язык запроса
curl -s "http://<analytics>/healthz"                      # -> {"language": "...", "languages": ["ru","en"]}
curl -s "http://<analytics>/?lang=en" | grep -o "Upload model"

# глобальная настройка
curl -X POST -H "Authorization: Bearer $ADMIN_KEY" "http://<ops>/settings/language?lang=en"
sleep 31                                                  # кэш 30 с
curl -s -H "Authorization: Bearer $ADMIN_KEY" "http://<testing>/scans/<id>" | jq -r .reason
```
