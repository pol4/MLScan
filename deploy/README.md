# Развёртывание MLScan: выберите нужный уровень

MLScan разворачивается **поэтапно**: каждый уровень самодостаточен (полностью работоспособен
в своих возможностях анализа), а следующий — только добавляет возможности и компоненты.
Можно остановиться на любом уровне или поставить сразу верхний.

План и аргументация уровней — [`../docs/13-deployment-plan.md`](../docs/13-deployment-plan.md).

## Уровни

| Ур. | Название | Что даёт | Что требует | Каталоги | Проверка |
|-----|----------|----------|-------------|----------|----------|
| **0** | **PoC** | Многоформатный статический анализ (pickle/torch/numpy, SafeTensors, ONNX, HDF5/Keras, GGUF, архивы, ноутбуки, скрипты, конфиги/карточки/токенизаторы, MCP, HTML/SVG, Dockerfile, датасеты, сжатые payload'ы), динамика в Docker и поведение (L3) для исполняемых форматов, отчёт MD/JSON, честный вердикт с покрытием | Python 3.10+, Docker (только для динамики) | [`poc/`](../poc) | `bash deploy/verify.sh 0` |
| **1** | **Изолированная песочница** | То же, но недоверенный код исполняется в **Kata microVM** на одном узле: сетевой запрет + sinkhole/honeypot, RO-FS, drop-all, лимиты, Falco/eBPF, отдача артефакта сервером | Kubernetes на 1 узле, RuntimeClass `kata`/`gvisor`, реестр образов | [`stage1/`](./stage1), [`sandbox-image/`](./sandbox-image) | `bash deploy/verify.sh 1` |
| **2** | **Сервис тестирования** | HTTP API приёма артефактов (потоково, большие файлы), дедупликация в **S3 (Garage)** `sha256/<name>`, метаданные и находки в **PostgreSQL**, оркестрация Job, вердикт с учётом покрытия, сообщения RU/EN | Ур. 1 + Garage + PostgreSQL | [`v2/data/`](./v2/data), [`v2/db/`](./v2/db), [`stage2/`](./stage2) | `bash deploy/verify.sh 2` |
| **3** | **Аналитика, Policy, Evidence, UI** | Скоринг, Policy Engine, append-only evidence с hash-chain (файл + зеркало в PG), отчёты JSON/MD/SARIF, веб-UI: вход (пользователи/API-ключи/роли), переключатель языка, `/settings` (глобальный язык), баннер неполной проверки | Ур. 2 + Ingress (Istio) | [`v2/auth/`](./v2/auth), [`i18n/`](./i18n), [`stage3/`](./stage3), [`ingress/`](./ingress) | `bash deploy/verify.sh 3` |
| **4** | **Интеграции** | Реестр моделей по SHA-256, CI-gate (`/gate` → allow/block/review и exit-code), SIEM-экспорт (NDJSON/CEF), threat-intel | Ур. 2–3 | [`stage4/`](./stage4) | `bash deploy/verify.sh 4` |
| **5** | **Эксплуатация** | Метрики Prometheus, `/quality` (TPR/FPR), `/sla`, `/retest` по cron, red-team Job, `/alerts`, retention/TTL + карантин + tombstones, backup/restore с проверкой, PDB, аттестация | Ур. 3–4 | [`stage5/`](./stage5), [`v2/lifecycle/`](./v2/lifecycle), [`v2/backup/`](./v2/backup) | `bash deploy/verify.sh 5` |

Зависимости уровней линейны: `0 → 1 → 2 → 3 → 4 → 5`; уровни 4 и 5 можно ставить в любом порядке
после 3, но 5 использует интеграции (реестр/гейт) в golden-наборе.

## Установка

```bash
bash deploy/install.sh 0        # PoC: печатает инструкцию (в кластере ничего не меняется)
bash deploy/install.sh 3        # уровни кластера: 1 → 2 → 3 со всеми зависимостями
bash deploy/install.sh 5        # сразу всё (идемпотентно, повторный запуск безопасен)

bash deploy/verify.sh 3         # сквозная проверка уровня
bash deploy/verify.sh 5 --full  # + полный прогон корпуса (141 образец, ~1 час)
```

Проверки предпосылок выполняются автоматически: скрипт сообщит, если нет `kubectl`/кластера,
RuntimeClass `kata`, Garage/PostgreSQL или доступа к Secret с ключами.

## Что выбрать

| Задача | Уровень |
|--------|---------|
| Разовая проверка модели «вручную», pre-commit, локальный CI-шаг | **0** |
| Сканировать недоверенные модели с сильной изоляцией на одном узле | **1** |
| CI/платформа: приём больших моделей, дедупликация, история | **2** |
| Нужен контроль решений (policy), доказуемый журнал (evidence) и UI для аналитиков | **3** |
| Встроить проверку в поставку моделей (гейт), отдавать события в SIEM | **4** |
| Промышленная эксплуатация: метрики, качество, хранение по TTL, бэкапы | **5** |

## Как устроена «поэтапность» в коде

* **Форматный анализ** — единый модуль [`poc/formats.py`](../poc/formats.py): один и тот же
  набор адаптеров используют и PoC (уровень 0), и сервис тестирования (уровни 2+),
  поэтому набор проверяемых форматов не зависит от уровня развёртывания.
* **Локализация** — [`i18n/`](./i18n): каталог RU/EN и правила перевода; в PoC — опционально
  (`--lang`), в сервисах — с уровня 2, в UI — с уровня 3.
* **Вердикт** — всегда учитывает полноту покрытия: модуль не отработал → `Inconclusive`
  с частичным результатом, а не «Safe». Работает на всех уровнях.
* **Хранилища** — файловые PVC (уровень 1) → S3 + PostgreSQL (уровень 2), append-only
  evidence с зеркалом в PG (уровень 3).

## Эксплуатация по уровням

| Команда | Уровни | Назначение |
|---------|--------|-----------|
| `bash deploy/install.sh N` | 0–5 | установка/обновление уровня (идемпотентно) |
| `bash deploy/verify.sh N [--full]` | 0–5 | сквозная проверка уровня |
| `python3 tests/vulnerabilities/run_tests.py --url … --key …` | 2–5 | корпус уязвимостей (TPR/FPR) |
| `bash deploy/upgrade.md` (инструкция) | 0–4 | переход на следующий уровень |
| `deploy/stageN/README.md` | 1–5 | детали компонентов этапа |

Дальше: **[`upgrade.md`](./upgrade.md)** — как перейти с уровня N на N+1, какие миграции выполнить
и как откатиться.
