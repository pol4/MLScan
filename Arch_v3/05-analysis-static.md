# 05. Статический анализ v3: потоково из S3

## 1. Задача

Провести **полноценный** статический анализ объекта 1 ТБ+, не загружая его целиком: читать только
заголовки/индексы/сэмплы, покрывать максимум значимых данных и **явно** отражать покрытие.

## 2. Модель исполнения

- **Range-read** из S3 (`range_get(key, off, len)`), параллельно (16–64 потока), с node-local кэшем.
- **Index-driven**: для форматов с индексом (safetensors, ONNX, HDF5, GGUF, zip) сначала читается
  индекс/оглавление, затем — только нужные диапазоны.
- **Sampling**: для «сырых» тензоров — выборочное чтение блоков (по стратегии: начало/середина/
  конец, стратифицированно), с учётом `coverage`.
- **Streaming для последовательных форматов** (tar/pickle-поток): чтение последовательно диапазонами.
- **Workers**: пул воркеров на compute-узлах; задания декомпозируются по диапазонам/чанкам.

## 3. Форматы и стратегии

| Формат | Что читаем | Полнота |
|--------|-----------|---------|
| safetensors | 8-байт header len + JSON index, затем сэмплы тензоров | index 100 %, данные — sampling |
| ONNX | protobuf-модель (потоково), внешние данные (range) | по возможности полный граф |
| HDF5/Keras | superblock + B-tree индекса, сэмплы датасетов | метаданные + sampling |
| GGUF | заголовок + индекс тензоров, сэмплы | метаданные + sampling |
| zip/архивы | центральный каталог (range), затем члены (`06`) | члены по бюджету |
| pickle/поток | последовательное чтение диапазонами, опкоды | до бюджета `MAX_OPCODES` |
| текст/скрипты/док | чтение целиком (они малы) или диапазонами | полный |
| «сырой»/unknown | сигнатуры + энтропия + embeds-строки | ограниченно |

## 4. Детекторы и версионирование

- Детекторы — **версионируемые** (semver) и подписанные; скан фиксирует их версию.
- Находки: `check_id`, `category`, `severity`, `confidence`, `evidence`, `range` (offset/len).
- Повторный анализ при смене версии правил — по требованию F11.

## 5. Покрытие (coverage) — первоклассно

Для каждой проверки фиксируется:
- процент прочитанных значимых диапазонов;
- какие модули/парсеры отработали;
- что пропущено и почему (лимит, время, размер).

Правило вердикта: если покрытие ниже порога для «clean»-вердикта → **`Inconclusive`** с причинами
(устранение частого ложного «Safe» из v2).

## 6. Производительность

- Параллельные range-read + кэш: целевое **время до первого результата ≤ 5 мин** (N3) и
  **полный статический разбор 1 ТБ ≤ 2 ч** (N4) при индексах/sampling.
- Бюджеты времени/байт на скан; по исчерпании — останов с честным покрытием.
- Cost model: число диапазонов × размер × скорость узла; планировщик учитывает.

## 7. Пример: safetensors 1 ТБ

```
1) range_get 0..8            -> header_len (~сотни КБ)
2) range_get 8..8+header_len -> JSON index (имена, dtype, shape, offsets)
3) для каждого тензора: сэмпл диапазонов (start/mid/end) для BD-эвристик (NaN/Inf)
4) проверка метаданных (__metadata__) на payload (EXEC-строки)
5) coverage: index 100 %, sampled tensors = доля; вердикт по policy
```
Не требуется чтение 1 ТБ данных — только индекс и сэмплы.

## 8. Интеграция с v2

`static_stage`/`formats.py` переиспользуются как «детекторы», но драйвер чтения заменяется на
потоковый (range-read), а `_read_bounded` ограничивается бюджетами. `total_size`-aware логика v2
(P1-6) сохраняется.
