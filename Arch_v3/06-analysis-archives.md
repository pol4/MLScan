# 06. Анализ архивов v3: членный обход 1 ТБ+

## 1. Задача

Комплексно проверить **архив 1 ТБ**, содержащий модели/артефакты всех поддерживаемых форматов,
потоково из S3, без материализации, с бюджетами и явным покрытием.

## 2. Ключевые идеи

1. **Оглавление по range**: для zip — прочитать «central directory» (в конце файла, через
   `range_get(size-K..size)`), не скачивая данные; для tar — последовательный стриминг заголовков.
2. **Член = диапазон**: каждый член — это `(offset, length)` в объекте; анализ читает строго
   диапазон члена (при необходимости — поддиапазоны).
3. **Параллельные member-workers**: члены обрабатываются пулом воркеров; тяжёлые — ограничиваются
   бюджетом.
4. **Вложенность**: член-архив рекурсивно раскрывается с **depth-бюджетом** и суммарным бюджетом.
5. **Индекс членов**: сохраняется манифест всех членов (имя, формат, диапазон, статус, покрытие) —
   для отчётов, rescan и частичного повторного анализа.

## 3. Алгоритм

```
A. Оглавление (index)
   zip: range_get(tail) -> central directory -> список членов (offsets, sizes)
   tar: sequential headers -> список членов (offsets, sizes)
B. План (планировщик)
   фильтр членов по бюджетам (размер, число, суммарный объём), приоритеты по формату
C. Обход (member-workers, пул)
   для члена:
     - определить формат (по имени/сигнатуре: range_get(head))
     - статика члена: потоково из S3 (см. 05), бюджет на члена
     - решение о динамике: если размер <= порога песочницы -> сэмплированная динамика (07)
     - если член — вложенный архив и depth не исчерпан -> рекурсия A..C (со своим бюджетом)
     - записать находки + покрытие члена
D. Агрегация
   нормализация, лимит находок (с пометкой), агрегатное покрытие архива
E. Вердикт
   max_severity/risk_score + policy; при неполноте -> Inconclusive
F. Evidence/отчёты
   PG + WORM + HMAC; JSON/MD/SARIF; карточка архива (список членов)
```

## 4. Бюджеты и политики

| Параметр | Значение по умолчанию | Назначение |
|----------|-----------------------|-----------|
| max members | 100 000 (настраивается) | защита от «бомбы членов» |
| max member size (static) | напр. 8 ГиБ (диапазонно!) | не читаем гигантский член целиком |
| total analyzed bytes | бюджет на скан | ограничение времени/стоимости |
| depth | 3–5 | вложенность |
| ratio-защита | zip/tar bomb | отказ при аномальном сжатии/расширении |
| dynamic threshold | лимит песочницы | для сэмплированной динамики |

При превышении бюджета — останов с фиксацией **что не проверено** (coverage/`Inconclusive`).

## 5. Форматы внутри архива

Все форматы из `13-formats.md`: safetensors, ONNX, HDF5/Keras, GGUF, TorchScript, pickle, скрипты,
ноутбуки, конфиги, датасеты, изображения, вложенные архивы и т.д. Каждый — своим детектором,
потоково; «неизвестные» — сигнатуры/энтропия/embeds-строки.

## 6. Производительность

Цель: **разбор архива 1 ТБ ≤ 4 ч** (N5) при типовом составе. Достигается:
- индексом (не читаем данные без нужды),
- параллелизмом членов,
- кэшем горячих диапазонов,
- приоритизацией (сначала — исполняемые/подозрительные форматы).

## 7. Частичный повторный анализ

Манифест членов позволяет:
- **rescan** только изменившихся/новых версий правил;
- пропуск уже проверенных членов по `(sha256 члена, версия правил)`;
- дельта-отчёты.

## 8. Безопасность обхода

- Парсинг оглавлений/членов — в **parser-sandbox** (изоляция) там, где это возможно (`08`).
- Защита от bomb/overlap/negative-offset/zip-slip и пр. — набор инвариантов валидации.
- Ни один член **не исполняется** в доверенной зоне; исполнение — только в Kata-песочнице.
