# 07. Динамический анализ v3: сэмплированная динамика

## 1. Задача

Проверять **поведение** моделей/кода, не требуя полной загрузки объекта 1 ТБ: работать на
**срезах/членах** в пределах лимитов песочницы, с бюджетами и явным покрытием.

## 2. Стратегии динамики

| Стратегия | Когда | Что делаем |
|-----------|-------|-----------|
| `full` | объект помещается в лимиты песочницы | полная загрузка + harness L2/L3 |
| `sampled` | крупные объекты/члены | сэмпл диапазонов/членов, запуск harness на фрагментах |
| `skip` | неисполняемые данные (изображения/датасеты) | динамика неприменима (coverage) |
| `llm-inference` | LLM-модель + образ движка инференса | запуск движка в изоляции Kata, наблюдение eBPF/Tetragon, пробы OpenAI API — см. [`16-llm-inference-testing.md`](16-llm-inference-testing.md) |

## 3. Сэмплированная динамика

- **Срез объекта**: формируется «представительная выборка» — заголовок/индекс + подмножество
  тензор-блоков, достаточное для загрузчика/поведенческих проб.
- **Срез члена**: для архивов — динамика запускается на отдельных членах (в бюджете), а не на архиве.
- **Бюджет**: `JOB_MEMORY`, `JOB_EPHEMERAL`, `JOB_TIMEOUT`, максимальный объём среза.
- **Явное покрытие**: какие срезы/члены реально проверены; остальное — «не проверено» в вердикте.

```
крупная модель ──▶ [ selector срезов ] ──▶ Kata Job: harness на срезах
                     │ header + index + sampled blocks
                     └─▶ findings + behavior coverage
```

## 4. Harness (переиспользуется из v1/v2)

- Загрузка загрузчиками по формату (safetensors/onnx/hdf5/keras/gguf/torch/pickle/…).
- Audit-hook: open/exec/subprocess/socket/dlopen/`os.system`; снимок состояния до/после.
- Поведенческие пробы: вызовы callable, поиск подозрительных строк.
- **Нонс результата**: маркеры с нонсом скана; сервис принимает только свои (антиподмена).
- Honeypot/sinkhole; среда Kata уничтожается после Job.

## 5. Управление и лимиты

- Песочница — **Kata microVM**, образ по digest, Kyverno-политика, read-only FS, drop ALL, seccomp.
- Egress — deny-by-default (+ DNS/sinkhole/артефакт-сервер по токену).
- Лимиты на срез/член; суммарный бюджет динамики на скан.
- При превышении — останов с фиксацией покрытия (`Inconclusive`).

## 6. Когда динамика невозможна

- Член/объект неисполняемого типа (данные) → `skip` (обоснованно).
- Формат не поддерживается загрузчиком (нет библиотеки) → `coverage.dynamic.failed` с причиной.
- Экономия: для ТБ-объектов динамика **никогда** не требует полной загрузки.

## 7. Отличия от v2

- v2: динамика «целиком», для ТБ — `skipped`.
- v3: **selector срезов** + динамика на срезах/членах; покрытие агрегируется; полноценная
  сэмплированная проверка поведения даже для крупных объектов.

## 8. Интеграция и тесты

- Селектор срезов — детерминированный (воспроизводимость) и версионируемый.
- Тесты: unit (селектор), e2e (Job на срезе реальной модели), perf (бюджеты), security (нонс,
  honeypot, egress). См. `12-testing-strategy.md`.
