# 12. Стратегия тестирования v3

## 1. Принципы

1. **Тесты сначала** для каждого этапа плана (`15-implementation-plan.md`): обновить/добавить тесты →
   реализовать → прогнать (unit+e2e+UI+perf) → довести до зелёного.
2. **Тесты с АРМ** (внешний клиент) — обязательны для ingest/API/S3.
3. **Масштабные harness’ы** — синтетические 1 ТБ модели и 1 ТБ архивы всех форматов.
4. **Проверяемость** — тесты проверяют не только «работает», но и метрики/покрытие/целостность.

## 2. Виды тестов

| Вид | Что покрывает |
|-----|---------------|
| Unit | s3client (multipart/range/presign/resume/retry), детекторы, selector срезов, бюджеты |
| Contract | API ingest/scan/evidence (схемы, коды) |
| E2E (in-cluster) | direct-upload, resume, prefix/static, archive member walk |
| E2E (с АРМ) | presigned через TLS edge, multipart, завершение/скан; изоляция тенантов |
| Perf | ingest ГБ/с, время статики/архива, capacity, дедуп-эффект |
| UI (браузер) | дашборд, карточка артефакта/архива, прогресс, язык, policy |
| Security | нонс результата, honeypot, egress, подпись образов, verify evidence |
| Chaos/DR | выход узла S3, рестарт control, восстановление, failover |
| Quality | golden-набор: TPR/FPR; покрытие; регрессия вердиктов |

## 3. Масштабные harness’ы (1 ТБ)

### 3.1 Модель 1 ТБ (safetensors)
- Генератор: валидный safetensors ~1 ТБ (индекс + «тензоры»), в т.ч. вариант с payload в метаданных.
- Проверки: время до первого результата (N3), полный анализ (N4), coverage, вердикт, метрики.
- Кейсы: чистый; с EXEC-строкой; битый индекс; обрезанный «тензор».

### 3.2 Архив 1 ТБ со всеми форматами
- Генератор: zip/tar ~1 ТБ, внутри — образцы **всех** поддерживаемых форматов (safetensors, ONNX,
  HDF5/Keras, GGUF, torch, pickle, скрипты, ноутбуки, конфиги, датасеты, изображения, вложенные
  архивы) + «зловредные» варианты.
- Проверки: индексация членов, member-walk ≤ N5, покрытие, агрегированный вердикт, отчёт карточки.
- Кейсы: bomb-архив, глубокая вложенность (depth-бюджет), zip-slip, огромный член.

## 4. Управление размерами в тестах

- «Огромные» тесты — **опциональные** (флаг), по умолчанию — уменьшенные репрезентативные размеры
  (например, 4–16 ГиБ), чтобы CI был быстрым; ночной прогон — полный 1 ТБ.
- Синтетика детерминирована (seeded) для воспроизводимости; sha фиксируются.

## 5. Окружения

- **CI (быстрое)**: unit/contract/e2e-small/UI; без 1 ТБ.
- **Ночное (полное)**: perf 1 ТБ model/archive; chaos/DR.
- **Стенд с АРМ**: внешние тесты через TLS edge.

## 6. Критерии приёмки (Definition of Done)

- Все тесты зелёные (unit+e2e+UI+perf для этапа).
- SLO (N1–N9) измерены и в норме на репрезентативных размерах.
- Evidence verify = ok; coverage/`Inconclusive` корректны.
- Документация обновлена (архитектура + план + отчёты тестов).

## 7. Артефакты тестов

Результаты perf/quality сохраняются в репозиторий (JSON) как историческая база (как в v2
`tests/perf/garage_ingest_result.json`), но с разделением по версиям.

## 8. Отличия от v2

- Добавлены: range-read тесты, archive member-walk, sampled dynamic, per-tenant изоляция, TLS/mTLS,
  chaos/DR, capacity-тесты и 1 ТБ harness’ы.
- Сохранены: строгий цикл «тесты → реализация → тесты», тесты с АРМ, golden-набор качества.
