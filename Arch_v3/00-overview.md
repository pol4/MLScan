# 00. Обзор архитектуры v3

## 1. Задача

Обеспечить **полноценную работу** с ML-моделями и архивами моделей/иных артефактов **размером
1 ТБ и больше**: приём, хранение, потоковый анализ (статика + выборочная динамика), комплексный
разбор архивов всех поддерживаемых форматов, достоверный вердикт, мультитенантность и
промышленная эксплуатация (HA, DR, SLA).

## 2. Почему v3, а не «доработка v2»

v2 (`../Arch_v2/03-v2-limitations.md`) доказала концепцию и дала инфраструктурную основу, но её
ключевые свойства не масштабируются на ТБ:

- **Single-node data-plane** (Garage, RF=1) — единая точка отказа и узкое место ingest (~40 МБ/с).
- **Двухходовой путь и материализация** — 1 ТБ нельзя скачать в сервис для анализа.
- **Обход архивов ограничен** (128 МиБ/архив) — ТБ-архив не проходится end-to-end.
- **Динамика «только целиком»** — для ТБ невыполнима.
- **Мультитенантность/ИБ/HA** — поверхностны.

v3 меняет три вещи принципиально: **(1)** data-plane становится распределённым и быстрым;
**(2)** анализ читает **только нужные диапазоны** объекта из S3 (без материализации);
**(3)** архивы обходятся **потоково, по членам**, с индексом и бюджетами.

## 3. Принципы v3

1. **Данные не покидают хранилище целиком.** Анализ работает через range-read/mmap-кэш; полная
   материализация допустима только для малых объектов.
2. **Ingest — direct-to-S3 по умолчанию.** Сервис анализа не в пути данных; загрузка параллельная,
   резюмируемая, с квотами.
3. **Content-addressed общий пул + тенант-ссылки.** Дедуп между тенантами; изоляция — через ACL,
   квоты и (опционально) per-tenant KMS.
4. **Явное покрытие.** Любая неполнота проверки отражается в вердикте (`Inconclusive`) с причинами.
5. **Безопасность по умолчанию.** TLS/mTLS, короткоживущие presigned-URL, sandbox (Kata),
   deny-by-default egress, подписанные образы/конфиги, WORM-анкоринг evidence.
6. **Мультитенантность как первоклассная сущность.** Квоты, fair-share, per-tenant SLO и метрики.
7. **Всё воспроизводимо и версионируемо.** Детекторы/политики/образы — версии и digest; GitOps.
8. **Честные границы.** Ограничения v3 документируются, а не скрываются.

## 4. Что нового относительно v2 (сводно)

| Область | v2 | v3 |
|---------|----|----|
| Data-plane | 1 узел Garage, RF=1 | ≥3 узла, RF≥2/erasure coding, шардинг, tiering |
| Ingest | ~40 МБ/с/узел | ≥1 ГБ/с/узел, агрегат ≥5 ГБ/с, NVMe hot-tier |
| Путь данных | 2 хопа, материализация | Direct-to-S3, потоковый range-read из S3 |
| Статика | префикс 64 МиБ | потоковый/инкрементальный обход, index/sampling |
| Архивы | лимит 128 МиБ/архив | членный стриминг 1 ТБ+, индекс, depth-бюджет |
| Динамика | целиком | сэмплированные срезы/члены, бюджеты |
| Мультитенант | префикс без квот | квоты, fair-share, KMS, изоляция |
| Транспорт | S3 passthrough без TLS | TLS/mTLS, короткий TTL presigned |
| Надёжность | single replica, ручные операции | HA, очереди/автоскейл, DR, GitOps |
| Наблюдаемость | общие метрики | per-tenant SLO, трейсинг, capacity model |

## 5. Ключевые определения

- **Артефакт** — объект в S3 (модель, архив, датасет, документ) с манифестом (sha256, размер, формат).
- **Скан** — задача анализа артефакта (одного объекта или членов архива) с политикой анализа.
- **Стратегия анализа** — `static` | `dynamic` | `archive` | `full` (по умолчанию автоподбор по размеру).
- **Покрытие (coverage)** — какие модули/члены/диапазоны реально проверены.
- **Тенант** — пользователь/CI/команда с квотой и изоляцией.
