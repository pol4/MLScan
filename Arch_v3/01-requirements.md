# 01. Требования v3

## 1. Функциональные требования

| ID | Требование | Приоритет |
|----|------------|-----------|
| F1 | Приём одного объекта (модель/архив) **≥ 1 ТБ** без материализации на сервисе | P0 |
| F2 | Прямая presigned-multipart загрузка клиентом (браузер/aws-cli/rclone/CI) напрямую в S3 | P0 |
| F3 | Возобновляемая загрузка (offset/части), устойчивость к обрывам и рестартам | P0 |
| F4 | Комплексный анализ архива **1 ТБ** со всеми поддерживаемыми форматами (в т.ч. вложенные) | P0 |

| F6 | Сэмплированная динамика (срезы/члены) с явным покрытием | P1 |

## 2. Нефункциональные требования (SLO)

| ID | Метрика | Цель |
|----|---------|------|
| N1 | Пропускная ingest на узел | ≥ 1 ГБ/с (NVMe), агрегат ≥ 5 ГБ/с |
| N2 | Утилизация канала ≥10 Гбит/с при прямой загрузке | ≥ 80 % |
| N3 | Время до первого результата статики для 1 ТБ | ≤ 5 мин (после доступности объекта) |
| N4 | Полный статический разбор 1 ТБ (index/sampling) | ≤ 2 ч |
| N5 | Разбор архива 1 ТБ (членный обход) | ≤ 4 ч (зависит от числа членов) |
| N6 | Доступность API | ≥ 99.9 % (месяц) |
| N7 | Долговечность данных | RF≥2 или erasure coding; RPO ≤ 15 мин, RTO ≤ 1 ч |
| N8 | Ложноположительные (FP) на golden-наборе | ≤ 1 % |
| N9 | Покрытие (доля проверенного) для типовых артефактов | ≥ 95 %; иначе явное `Inconclusive` |
| N10 | Готовность динамики (при размере ≤ порога) | ≥ 99 % успешных Job |
| N11 | Стоимость хранения | tiering hot/cold, дедуп ≥ 30 % на повторных загрузках |

## 3. Ограничения и допущения

- Артефакт может быть **враждебным** (произвольный payload, обфускация, «контейнеры-матpёшки»).
- Объект может быть **несжимаемым** (raw-тензоры), поэтому дедуп/сжатие не гарантируют экономии.
- Клиенты — браузеры (без спец-клиента) и CI (aws-cli/rclone/наш клиент).
- Развёртывание — Kubernetes; хранение — S3-совместимое.
- Сеть клиент→кластер: **≥ 10 Гбит/с** (LAN); межсайтово возможен высокий RTT.
- Секреты — в KMS/Secret; люди — через OIDC (интеграция с существующим IdP).

## 4. Границы (что v3 сознательно НЕ обещает)

- Гарантированный «детект всего» — только детект известных классов + честное покрытие.
- Полная динамика объектов, не помещающихся в лимиты песочницы (только сэмплирование).
- Расшифровка произвольных E2E-шифрованных артефактов клиента (по согласованной модели — см. `08`).
- Бесконечно глубокие вложенные архивы (depth-бюджет; см. `06`, `14`).
