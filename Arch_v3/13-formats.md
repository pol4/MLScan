## 2. Детекторы и их версии

- Каждый детектор — `check_id`, категория, severity, confidence, **версия**.
- Реестр версий: скан фиксирует набор версий; повторный анализ при апдейтах (F11).
- Правила «что считать подозрительным» — в политике/детекторах, не в коде оркестратора.

## 3. Расширяемость

- **Новый формат**: детектор (сигнатура) + парсер (потоковый) + правила; регистрация в реестре.
- **Новая проверка**: детектор + (опц.) поведенческая проба в harness.
- **Новые бюджеты/политики**: параметры планировщика/оркестратора.
- Парсеры выполняются в **parser-sandbox** (изоляция новых/недоверенных парсеров).

## 4. Требования к парсерам v3

- Только чтение по диапазонам; без исполнения и без полной загрузки.
- Устойчивость к некорректным данным (negative/overlap/overflow/zip-slip/bomb).
- Детерминированные бюджеты (байты/время), возвращают покрытие прочитанного.
- Фаззинг-тесты обязательны для новых парсеров (§`12`).

## 5. Совместимость с v2

Детекторы v2 (`poc/formats.py`) переиспользуются; драйвер чтения заменяется потоковым. Форматные
волны v2 (1–7) сохраняют нумерацию `check_id`; новые правила v3 продолжают нумерацию.
